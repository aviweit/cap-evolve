Optimizing using the blackbox approach

In the blackbox approach the optimizer process never touches the benchmark.

Some clients, such as enterprises, cannot share their agent's code, sources or behaviour with an external optimization process. For them the optimization runs indirectly, without inspecting or directly modifying their agents.

The approach introduces two additional services:

  • Skillberry Store: a smart repository of tools and skills for agentic workflows.
  • Skillberry Proxy-Agent: a proxy that sits between the client agent and the LLM provider, uses the optimized skills and tools, and returns an optimized response to the agent.

cap-evolve deploys the capabilities to optimize (system prompts, tools, skills) into the Skillberry Store, and the Skillberry Proxy-Agent reads them and injects them into the agent's LLM calls. The benchmark agent is left unchanged: it receives the optimized response from Skillberry.

There are two ways to use the optimized capabilities:

  1. Through the Skillberry service (a paid service): the client never changes its benchmark. The benchmark is optimized through the responses the Skillberry Proxy-Agent returns.
  2. By exporting the optimized capabilities from the Skillberry Store and patching them back into the client's benchmark.

Configure and run

A capability is what gets edited (capabilities:). An intervention is how the edited candidate reaches the model under test (intervention:). Below is the worked τ²-bench example, which uses the blackbox approach to optimize the airline agent's tools (capabilities: [tools]).

Environment variables, in the repo-root .env:

# the model the Skillberry Proxy-Agent calls
SPA_MODEL_NAME=<proxy-agent model>
# the gateway model of the agent under test
TAU2_AGENT_MODEL=<agent model>
# the user simulator's model
TAU2_USER_MODEL=<user model>

The run spec, capevolve.yaml: the keys that select the blackbox approach and the tools capability, as in the smoke spec (capevolve.smoke.yaml): 

# delivery
intervention: blackbox
skill_name: my_skill              # required: the one skill the Proxy-Agent serves

# what to optimize
capabilities: [tools]             # the agent's tool surface only
capability_path: seed_capability  # the seed; a copy is optimized
capability_sources: [seed_capability/reference/data_model.py]

# smoke: task 9, one trial, one iteration, mock optimizer
optimizer_skill: mock
split_ids_file: split_ids_smoke.json
num_trials: 1
max_iterations: 1

Going further Work in progress

To use the blackbox approach on your own benchmark, its runner must route only the agent to the sentinel, send the context headers, expose its environment over HTTP, merge both trajectories in the right windows, open and close a session per trial, and deploy the candidate in apply(). The example was produced by an agent following an onboarding prompt.
